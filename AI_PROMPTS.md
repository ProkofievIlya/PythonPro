# AI Prompts

Інструмент: AI-асистент (чат). Усі відповіді AI перевірялись вручну; невалідні рекомендації відхилялись (див. `AI_REVIEW.md`).

## 1. Code review

```
Ти — senior Django-розробник. Зроби code review цих трьох в'ю інтернет-магазину
(checkout, checkout_success, stripe_webhook): знайди проблеми з безпекою, обробкою
помилок, логуванням, читабельністю. Для кожної рекомендації вкажи, чому вона важлива.
Не пропонуй змін, які ламають поточну поведінку, і не переписуй код цілком.
```

```
Для кожної рекомендації оціни, чи вона валідна саме для цього проєкту
(Stripe мокається в тестах, order резервує stock у транзакції). Що з цього варто застосувати, а що ні?
```

## 2. Генерація тестів

```
Напиши pytest-django тести для моделей Category, Book, Order, OrderItem. Використовуй фабрики
з tests/factories.py (factory-boy), parametrize там, де доречно, та перевіряй граничні випадки:
fallback локалізованих полів, межі in_stock, NULL у unique-полі stripe_session_id, снапшот ціни
в OrderItem, line_total з копійками. Не дублюй тести з tests/unit/test_models.py.
В кожен тест додай коментар: "# Generated with AI, reviewed and modified".
```

```
Напиши тести для змін після code review: логування помилки в checkout (mock logger),
вебхук без id сесії, вебхук для невідомого замовлення, вебхук незв'язаної події.
Stripe не викликати, використовуй fixture stripe_webhook_event.
```

- Відхилено звуження `except Exception` у `checkout` та перевірку `amount_total` у вебхуку (причини в `AI_REVIEW.md`).
- Тести моделей перевірено на відсутність дублікатів із наявними й підправлено очікування (наприклад, `stripe_session_id` за замовчуванням `None`, а не порожній рядок).
